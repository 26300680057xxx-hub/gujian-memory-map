# 给 ChatGPT 的开场提示词（复制即用）

> 用法：上传 `gujian-memory-map-gpt.zip` 后，把下面【第一段】整体粘贴发送。
> 之后每次想改东西，套【第二段】的模板提需求即可。

---

## 第一段：开场提示词（上传 zip 后第一次对话用）

```
你是资深前端工程师。我上传的 zip 是「华流古建 · 记忆地图」项目源码——
一个山西古建筑主题的古风互动网站（Vite + React 18 + TypeScript + Tailwind + shadcn/ui，
单页应用，无后端），是高校 HACKATHON 参赛作品，10 月 9 日截止，所以改动要稳、不要大重构。

请先完整阅读 zip 里的《GPT交接说明.md》，并浏览 src/data/sites.ts、
src/components/SiteDialog.tsx、src/components/PaintingMap.tsx、src/index.css
这四个核心文件，然后回复我一份简短确认：
1）你用一句话说明这个项目是做什么的；
2）你列出关键文件与对应职责（证明你读懂了结构）；
3）不要急着改任何代码，等我提需求。

后续每次修改请遵守这些规则：
- 只改我点名的文件，无关文件不要动；
- 输出「完整文件内容」，不要只给片段或 diff，我要整份复制粘贴回去；
- 每次回复开头先列出：本次改了哪几个文件、每个文件改了什么（一两句话说清）；
- 保持现有设计语言：宣纸+墨色+朱砂的暗色古风，配色和动画规范见交接说明文档；
- 文案用中文，文风与现有文案一致；
- 不要引入新的依赖包，除非我先同意；
- 改完主动提醒我需要在本地跑 npm run build 验证；
- 如果我的需求你判断会破坏现有效果或风险大，先说风险，给我替代方案，不要闷头改。
```

## 第二段：日常提需求模板（每次修改套这个格式）

```
需求：【用大白话说清楚要改什么，例如：把乔家大院的出场动画改慢一点，
       现在 3.4 秒太快了，我想要 5 秒左右】

范围：【可选。如果你知道大概涉及哪里就写上，例如：应该在 SiteDialog.tsx 的
       REVEAL_MS 或 fly-through 动画上；不确定就写"你判断"】

要求：【可选。例如：其他记忆点的动画时长不要受影响】

请按规则输出完整文件内容。
```

### 几个真实需求示例（可直接改用）

- `需求：把弹窗里"记忆碎片"版块每个卡片之间间距加大一点，现在看着有点挤。范围：SiteDialog.tsx。`
- `需求：给小西天的黑神话悟空剪影加一句新的浮现文案，两句轮着显示。范围：你判断。要求：原句"既见未来·为何不拜"保留。`
- `需求：网站标题和浏览器标签页标题改成"华流古建 · 记忆地图 | 502.5队"。范围：你判断。`
- `需求：我想再加一个记忆点"平遥古城"，数据你先按乔家大院的结构编一版占位文案。范围：src/data/sites.ts。要求：地图上的位置你告诉我需要补什么素材，不要自己乱画坐标。`

## 拿回代码后你要做的三步

1. 把 GPT 给的完整文件内容，覆盖粘贴到本地项目对应文件（项目目录：`gujian-memory-map`）
2. 在项目目录运行 `npm run build`，不报错就说明代码没问题
3. 运行 `npm run dev` 打开预览看效果；不满意就把截图或报错发给 GPT 继续改（也可以发给我修）
